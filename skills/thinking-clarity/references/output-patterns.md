# Output Patterns

Use these patterns when a structured answer improves clarity.
These are output skeletons, not rigid forms. Use the lightest pattern that still makes the answer clear.

## Pattern 1: Quick Reframe

Use when one core ambiguity is blocking progress and the user mainly needs a cleaner framing plus one immediate next move.
If you are already comparing facts, constraints, or candidate interventions, this is too light.

- surface question
- real goal
- framing problem
- reframed question
- next move

## Pattern 2: Structured Analysis

Use when multiple facts, constraints, or tradeoffs need to be made explicit and compared.
This is the default for scope, sequencing, architecture, prioritization, and "what should we do now?" questions, even if the prompt mentions someone else's claim.

- real goal
- decision-relevant facts
- hard constraints
- soft constraints when relevant
- options or moving parts
- recommendation
- next move

## Pattern 3: Pressure Test

Use when an existing argument, proposal, or explanation needs to be challenged for weak assumptions, contradictions, or unsupported conclusions.
Use this only when claim scrutiny is the center of the answer. A quoted opinion inside a broader scope or prioritization decision does not automatically make this the right pattern.

- claim under test
- weak assumptions
- missing evidence or contradiction
- what survives scrutiny
- recommendation
- next move
