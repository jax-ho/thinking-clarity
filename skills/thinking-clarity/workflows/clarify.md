# Clarify Workflow

Use this workflow to identify the real question before trying to solve it.

## When to use

- the user's question is vague or overloaded
- key terms are undefined
- the user is mixing goal and method
- a tactical question is hiding a strategic one
- this issue feels confused because the framing is still weak

## Core question

What is the user actually trying to decide, understand, or achieve?

## Process

### Step 1: Restate the surface question

Write the question as the user currently frames it.

### Step 2: Identify vague or overloaded terms

Look for terms such as:

- better
- scalable
- necessary
- worth it
- simple
- risky
- professional

Ask what each term means in this specific context.

### Step 3: Separate goal from method

Check whether the user is naming:

- the real outcome
- a preferred method
- a fear
- a constraint
- a proxy metric
- a social expectation

Do not assume the preferred method is the real objective.

### Step 4: Surface initial assumptions

Identify the first layer of framing assumptions in the question.

### Step 5: Rewrite the problem cleanly

State the sharpest version of the actual question.

### Step 6: Give the smallest useful forward move

If clarification alone materially helps, end with one immediate next move such as:

- the sharper decision the user should answer next
- the fact that most needs validation
- the workflow that should follow

## Handoff rule

Stop once the question can be rewritten clearly. If the reframed question is now asking which underlying problem, cause, or constraint is actually driving the situation, move to `workflows/deconstruct.md`. If clarification alone already resolves the blockage, end with the narrower question and the next move.

## Output format

- surface question
- ambiguous terms when relevant
- initial assumptions
- real goal
- reframed question
- next move

## Quality bar

A good clarification should make the problem narrower, more precise, and easier to evaluate. It does not need to choose a full solution, but it should still leave the user with a clearer next move.
